# Master Checklist

The entire journey on one page. Detail lives in [VISION.md](VISION.md) and
[ROADMAP.md](ROADMAP.md); this is the simplest honest form of it.

Progress is measured in **users, downloads, and repos governed** — not stars.

## Stage 1 — Build it ✅

- [x] Protocol written, adversarially cross-reviewed by two AI models, frozen (v3.1.1)
- [x] Proven on a real production app with a known answer key
      (gates alone 1/7 · registry layer 7/7 · cure 4 full + 3 partial ·
      the cure itself drifted — audits are load-bearing)
- [x] CLI shipped: `plan` / `init` / `check` / `audit` / `baseline` / `waiver` + drift score
- [x] Cross-reviewed pre-release; verdict-integrity bugs fixed before v0.1

## Stage 2 — Launch it ✅

- [x] Public repo, npm package (3 releases), wiki, roadmap, vision, case study
- [x] Story published (dev.to, LinkedIn); newsletter submission out
- [x] First user → two real bugs → two same-day fixes → first outside
      contributor → Windows CI green (#1, #3, #4)

## Stage 3 — Prove it ← current

- [ ] Show HN, once the account is eligible
- [ ] 5 external repos running `asdlc check` in CI (free audits for OSS projects)
- [ ] 1,000 npm downloads/month
- [ ] Same-day fixes for everything users file — responsiveness IS the brand
- [ ] The private pilot repo accepts its baseline: governed install #1

## Stage 4 — Standardize it

- [ ] v1.0: 3+ validated external pilots; drift-score weights recalibrated on real data
- [ ] Python stack adapter
- [ ] Drift badges appearing in other people's READMEs
- [ ] Spec v3.2 — unfrozen only by validation-log evidence
- [ ] Tell the story out loud (talk / podcast)

## Stage 5 — Make it unavoidable

- [ ] Zaya MVP: governed harness where "done" is machine-verified
      (fork base selected — see [docs/ZAYA_EVALUATION.md](docs/ZAYA_EVALUATION.md))
- [ ] Builder / auditor / healer as separate sessions in one harness
- [ ] Commercial layer (hosted audits, org dashboards) — only if Stage 4 lands

## Standing rules — never expire

- [ ] Never overclaim; honest limits are the moat
- [ ] Every approval leaves a pointer — no exceptions
- [ ] Evidence before spec changes; users before features
- [ ] Each stage funds the next with proof, not promises
